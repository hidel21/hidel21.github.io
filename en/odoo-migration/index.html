Odoo migration to recent versions without downtime

I upgrade Odoo instances with custom modules from older versions to the latest ones, protecting data integrity and with a cutover plan that doesn't slow your team down.

Why migrate

  • Support and security: Odoo supports the last three major versions; older ones stop receiving fixes.
  • Up-to-date localizations: tax changes land first — or only — in recent versions.
  • Performance and usability improve with every release.
  • Cost: the longer you wait, the more versions you have to jump and the more code you have to adapt.

What changes between versions

The hard part isn't the data, it's the custom code. A few changes that break custom modules:

  • Odoo 17 replaced attrs and states in views with direct expressions in invisible, readonly and required.
  • Odoo 17 moved from name_get to _compute_display_name.
  • Odoo 18 renamed tree views to list.
  • Standard models and fields get renamed or removed: what a module extended in v14 may not exist the same way in v18.

I wrote a detailed guide (in Spanish) with before/after code: migrating Odoo modules from 16 to 18.

My migration process

  1. Inventory: standard, OCA and custom modules, and which ones are still needed (sometimes the new version already covers it).
  2. Data migration on a copy, using Odoo's upgrade service (Enterprise) or OpenUpgrade (Community), plus custom pre- and post-migration scripts.
  3. Custom code adaptation to the target version's API, with automated tests.
  4. Validation with key users: accounting closes, payroll and reports compared against the old version.
  5. Planned cutover: short freeze, backup, final migration and rollback plan.
  6. Hypercare during the first closes on the new version.

FAQ

Can I go straight from Odoo 14 to Odoo 18?

Yes. With Odoo's upgrade service (Enterprise) data can be moved in a single process; with OpenUpgrade (Community) you go version by version. Custom code always has to be adapted to the accumulated changes — which is what I did migrating Payroll, Accounting and Budget from v14 to v18.

How long does an Odoo migration take?

It depends on the number of custom modules, data volume and integrations. After the inventory I deliver a plan with phases and dates.

Will operations stop during the migration?

Not during development: everything runs on a copy of the database. There's only a short, scheduled cutover at the end.

Which version should I migrate to?

Usually the most recent one where the modules and tax localization you need are stable. I verify that during the assessment before recommending it.
